# CONTEXT

Краткий снимок **целевого** ML-продукта для агента. Держать компактно: ориентир **≤20 bullets** всего; за цикл добавлять **не больше 3** устойчивых выводов.

Профиль: E-CUP 2026, задача 3 «Ценность пользователей поиска». Пороги и сплиты — [`config.yaml`](../config.yaml). KPI — [`METRICS.md`](METRICS.md).

## Продукт и цель

- Предсказать суммарный GMV пользователя в Поиске и Каталоге за следующие 30 дней (оценка LTV «здесь и сейчас»).
- Тестовый горизонт соревнования: 2026-02-14 … 2026-03-15; история в train: 2025-01-01 … 2026-02-13.
- Нельзя менять без явного разрешения: метрику RMSLE, формат сабмита `user_id, predict`, множество всех клиентов (~250k), клип отрицательных предсказаний в 0.

## Данные и сплиты

- Источник: [`data/train.parquet`](../../data/train.parquet) (~30.6M строк, ~250 row groups). Не читать целиком в чат.
- Колонки: `event_date`, `user_id`, флаги `search`/`cat`, флаги и счётчики cart/ord по каналам, `gmv_search`/`gmv_cat`/`gmv`, `to_cart`/`to_ord`, `searches`.
- Строка = день с ненулевой (или записанной) активностью; это прореженные ряды. Полное дозаполнение нулями может раздуть данные ~до 100M строк — запрещено (`no_dense_zero_fill`).
- `primary_split`: cutoff 2026-01-14, таргет сумма `gmv` за 2026-01-15…2026-02-13.
- `holdout_splits`: cutoff 2025-12-15, таргет 2025-12-16…2026-01-14.
- Утечки: фичи только из дат ≤ cutoff; не использовать строки из окна таргета; не подгонять правила под конкретных `user_id`.
- Лидерборд 20/80 public/private по клиентам; офлайн-сплит — прокси, не тот же split.

## Пайплайн (высокоуровнево)

- Агрегаты/последовательности по пользователю до cutoff → модель 30d GMV → `max(0, pred)` → RMSLE vs сумма `gmv` в окне (нет строки = 0).
- Эксперименты: код, pred, meta — [`../workspace/`](../workspace/) (`ltv_arms.py`, `ltv_data.py`, `runner.py`). Knowledge-цикл — эта папка.
- Control: naive last-30d. Champion: H52 `lgb_btyd_ipi`, `champion_run: h52_ipi` в [`config.yaml`](../config.yaml).
